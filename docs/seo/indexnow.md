# IndexNow

Запускается вручную после деплоя, без аккаунтов в вебмастерах. Никаких build/deploy hooks нет.

## Команды

```sh
npm run indexnow
npm run indexnow -- --all
```

Первая команда выбирает изменённые индексируемые страницы последнего коммита. Вторая выбирает все индексируемые URL опубликованного sitemap, сейчас 93. После первого деплоя интеграции один раз запускается `--all`.

Проверка без POST:

```sh
npm run indexnow -- --dry-run
npm run indexnow -- --all --dry-run
npm run indexnow -- --all --dry-run --sitemap-dir dist
```

Без `--sitemap-dir` sitemap скачивается с hopscup.tools. Для офлайн-проверки сначала выполните `npm run build`. Локальный sitemap допустим только при `--dry-run`.

Можно проверить другой коммит: `npm run indexnow -- --commit <hash> --dry-run`. Сравнение всегда идёт с первым родителем выбранного коммита. При shallow clone нужно скачать историю; если родитель недоступен, скрипт завершается без отправки.

## Как выбираются страницы

Скрипт читает sitemap.xml и вложенные sitemap через XML-парсер. URL должны принадлежать HTTPS-хосту hopscup.tools, быть в sitemap и проходить текущий indexPolicy. Hreflang-ссылки не считаются URL sitemap. Noindex-страницы не отправляются, даже если ошибочно оказались в XML.

Режим последнего коммита сравнивает модели страниц в Git: OFFERS, редакционные блоки, метаданные, факты, гайды, лендинги, индексируемые маршруты и результаты общего рендеринга ссылок. Это не фильтр по дате сборки. Изменения общих компонентов, CSS и каркаса приложения консервативно включают все открытые страницы, поскольку меняется общий рендер. Изменения только инструментов IndexNow не делают страницы изменёнными. Незакоммиченный код не участвует в сравнении.

При пустом списке POST не выполняется. После коммита самой интеграции ожидается пустой changed-список: для первого запуска нужен явно согласованный `--all`.

## Ключ и проверки

Публичный ключ находится в indexnow.config.json. Его UTF-8 файл public/<key>.txt копируется Vite в корень сайта. Это не пароль; при смене ключа обновляйте конфиг и файл вместе.

Перед POST скрипт проверяет на проде ключ, HTTP 200, robots/X-Robots-Tag и canonical каждой выбранной страницы. Любая ошибка останавливает отправку до первого POST. Редиректы не выполняются автоматически.

## Ответы и лимиты

Один POST содержит не более 10 000 URL. Пакеты отправляются на оба явно настроенных endpoint: api.indexnow.org/indexnow и yandex.com/indexnow. Участники протокола также обмениваются уведомлениями между собой.

- 200: сервис принял уведомление, но это не гарантия индексации.
- 202: уведомление принято, проверка ключа ещё выполняется.
- 400/403/422: ошибка формата, ключа или адресов, код выхода 1.
- 429: ограничение частоты. Retry-After и rate-limit headers записываются в журнал. Автоматических повторов нет; следующие пакеты этого endpoint не отправляются.

Фиксированный общий дневной лимит не опубликован. Не повторяйте отправку неизменённых URL без причины.

JSON-журналы сохраняются в .indexnow/ и не попадают в Git. Они содержат режим, коммит, выбранные адреса, лимит пакета, HTTP-статусы, тела ответов и Retry-After. Таймауты и сетевые ошибки также записываются, код выхода ненулевой.
